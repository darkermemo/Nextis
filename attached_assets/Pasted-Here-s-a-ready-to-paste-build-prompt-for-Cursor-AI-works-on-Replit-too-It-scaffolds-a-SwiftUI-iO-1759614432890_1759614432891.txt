🔧 Cursor/Replit Build Prompt — “WeekMind” iOS App

Goal: Build a SwiftUI iOS app “WeekMind” with 3 tabs:
	1.	Chat (default): Top “Next 3” actions, text box to type commands.
	2.	Tasks: Simple list grouped by Today / This Week / Later.
	3.	Calendar: Week view showing scheduled blocks & events.

Behavior:
	•	Parse messages like:
“I have exam on economics next Friday.”
“Meeting Thursday at 9:00 pm.”
“I have 3 homeworks next week.”
“Add coffee breaks and TV time.”
“I feel tired today; I have work early tomorrow.”
	•	Create tasks/events, schedule study/prep blocks, insert breaks/leisure, set reminders (2 days before + 5 hours before), generate short quizzes pre-exam, show Next 3.
	•	Mood check-in modifies schedule (tired → shorter work, earlier sleep).
	•	Sleep policy: no heavy tasks within 90 minutes of bedtime; if “work early tomorrow,” set an earlier bedtime and reshuffle evening.

1) Data Models (Sources/Models)

Implement Swift models:

enum ItemType: String, Codable { case task, event, breakTime, leisure, quiz }
enum Priority: String, Codable { case high, normal, low }
enum Mood: String, Codable { case tired, stressed, motivated, focused, relaxed, none }

struct WMItem: Identifiable, Codable, Hashable {
  let id: UUID
  var type: ItemType
  var title: String
  var notes: String?
  var start: Date?
  var end: Date?
  var durationMinutes: Int?
  var deadline: Date?
  var fixed: Bool // events/meetings are fixed; blocks can move
  var priority: Priority
  var subtasks: [WMSubtask]
  var reminders: [Date] // absolute reminder times
  var tags: [String]
  var done: Bool
}

struct WMSubtask: Identifiable, Codable, Hashable {
  let id: UUID
  var title: String
  var done: Bool
}

struct NextActions: Codable {
  var items: [WMItem] // top 3 candidates in priority order
}

struct UserPrefs: Codable {
  var workStartHour: Int
  var workEndHour: Int
  var bedtimeHour: Int
  var allowEveningStudy: Bool
  var defaultTVStartHour: Int
}

struct DayState: Codable {
  var mood: Mood
  var hasEarlyWorkTomorrow: Bool
}

4) LLM Connector (Services/LLM)

Create LLMClient.swift with pluggable backends:

protocol LLMClient {
  func parseCommand(_ text: String, now: Date, timezone: TimeZone) async throws -> ParsedIntent
}

struct ParsedIntent: Codable {
  enum Kind: String, Codable {
    case addExam, addMeeting, addHomeworks, addBreaks, addLeisureTV, setMood, setEarlyWork, genericTask
  }
  var kind: Kind
  var title: String?
  var date: String?
  var time: String?
  var count: Int?
  var dueRange: String?
  var durationMinutes: Int?
  var priority: Priority?
  var mood: Mood?
  var earlyWorkTomorrow: Bool?
}

Function-calling prompt spec (send to LLM):

System: “Extract a single JSON object matching this schema. Do not explain.”
User text examples:
	•	“I have exam on economics next Friday” → {kind:"addExam", title:"Economics Exam", date:"2025-10-10"}
	•	“Meeting Thursday at 9:00 pm” → {kind:"addMeeting", title:"Meeting", date:"2025-10-09", time:"21:00"}
	•	“I have 3 homeworks next week” → {kind:"addHomeworks", count:3, dueRange:"next-week"}
	•	“I’m tired today” → {kind:"setMood", mood:"tired"}
	•	“I have work early tomorrow” → {kind:"setEarlyWork", earlyWorkTomorrow:true}
	•	“Add coffee breaks and TV time” → {kind:"addBreaks"} and {kind:"addLeisureTV"}

Implement OpenAI backend using the Chat Completions (JSON mode) with LLM_MODEL. Keep the provider swappable.

5) Planner / Agent (Features/Planner + Services/Scheduling)

Create PlannerEngine.swift:
	•	Input: Current items, ParsedIntent, UserPrefs, DayState, now.
	•	Output: Mutated items + generated schedule blocks + reminders + next actions.

Policies (hard-code for MVP):
	•	Events/meetings: fixed, add reminders D-2 and T-5h.
	•	Exams: add event (time TBD or evening), create study blocks Mon–Thu (25–90m), quiz micro-sessions (10–15m Tue–Thu), cram 30–45m Thu evening (avoid conflict).
	•	Homeworks: create N tasks due by next Friday; distribute blocks across Mon–Thu next week evenings.
	•	Breaks: insert 10–15m every ~90m of work.
	•	TV: default nightly 22:30–23:00 if free.
	•	Mood tired/stressed: shrink or swap hard blocks to lighter review; if hasEarlyWorkTomorrow, advance bedtime by 60–90m; no heavy work ≤90m before bedtime.

Scheduling algorithm (greedy + repair):
	1.	Sort items by urgency (deadline proximity, priority).
	2.	Place fixed events.
	3.	Fit blocks into free slots inside working hours; respect bedtime policy.
	4.	If overflow, push low-priority blocks; keep a change log for the UI.

Expose functions:

func apply(intent: ParsedIntent, state: inout AppState, now: Date)
func recomputeNextThree(state: AppState, now: Date) -> NextActions
